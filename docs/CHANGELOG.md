# Changelog

Each entry: what changed and why, then the evidence. Measurements live in [baseline.md](baseline.md).

## 2026-11-22

- **Remove the rule-based reranker and the scripts `test_models.py`, `test_cohere_rerank.py` and `migrate_html_chunks.py`.** Nothing in the pipeline used them, and `test_models.py` read `met` where the judge returns `present`.
  Evidence: no references remain (`git grep`); 176 tests pass with the database tests.
- **The answer model is Anthropic only; `SUPABASE_KEY`, `LLM_PROVIDER` and `OPENAI_API_KEY` are no longer settings.** The OpenAI path was switched off and the anon key was never read; a `.env` that still sets one now fails at startup, naming the key.
  Evidence: `tests/test_config.py` (each removed key gives exactly one `extra_forbidden` error on that key); 179 tests pass with the database tests.
- **Remove `PUT /documents/{id}` and `POST /ingest`.** Renaming a version left its old title in every chunk, and an upload was promoted at once, even a candidate from a new address; `scripts/load_corpus.py` is the way to load.
  Evidence: `test_documents_are_read_only` failed with the PUT route present and passes now; `test_ingest_is_gone`; 169 tests pass with the database tests.
- **Tables, functions and endpoints use the store's words: `versions`, `chunks`, `answers`, `answer_versions`; `GET /versions`, `GET /answers/{id}`; keyword search removed from the schema.** One word per thing in schema, code and docs; keyword search had no caller since the hybrid search went.
  Evidence: `test_no_old_store_names` listed every old table, column and endpoint name before and none after; 173 tests pass with the database tests.
- **Levels and scopes are tables; a source's rank comes from its level, and higher rank wins; an answer records its detected scope as a reference, matched as a whole word on the scope key.** Rank was stored on every source as well as in the loader, scope values were free text, and the detected scope sat in JSON nobody read.
  Evidence: database tests for unknown level, unknown scope, duplicate rank, the stated rank direction and the scope foreign key on answers; "Bekzahl" no longer matches `ekz`; 183 tests pass with the database tests.
- **Sources are identified by a fixed readable key; title, issuer and listing address are gone from sources; the database refuses a source of a scope-requiring level without a scope.** The loader matched sources by title, so renaming a title made a new source, and the scope rule lived only in Python.
  Evidence: database tests for key format, immutable key, `save_source` replacing scopes and level, and the deferred scope rule on insert and on removing the last scope; 190 tests pass with the database tests.
- **A source's watch address is set by a person (`corpus.yaml`), and adding the source or changing that address stamps `confirmed_at`; a version's `obtained_from` cannot change; promotion no longer moves the source's address.** The address moved silently on every promotion and the confirmation date was never written.
  Evidence: database tests: a new source is confirmed, the same address keeps the date across transactions, a new address gives a later date, `obtained_from` cannot be changed, promotion leaves the source untouched; 195 tests pass with the database tests.
- **Versions record the title and version label as printed and the page limit they were loaded with; the prompt, citations and chunk header show title and label; `file_path` is gone.** The label was hand-written into the title, the page limit lived only in `corpus.yaml`, and the baseline script found versions by local path.
  Evidence: database tests for a positive page limit, immutable label and page limit, no `file_path` column, `match_chunks` returning the label; prompt, formatter and loader tests; 203 tests pass with the database tests.
- **`corpus.yaml` defines levels, scopes and sources by key, with each version's printed title and label; the loader stops when the store holds a source that `corpus.yaml` no longer lists.** A renamed key would otherwise leave the old source current and searchable; unknown levels and scopes are reported by source before anything is written.
  Evidence: loader tests for an unlisted stored key, unknown level and scope, a source the database refuses while others still load; the checked-in corpus parses to 10 sources and 11 versions with unchanged paths and addresses; 210 tests pass with the database tests.
- **Flags have a running number, a reason, and fixed lists for kind, reason, resolution and who resolved them; `detail` names the file or the address.** Kind and resolution were free text or held unused values, and `detail` was always empty.
  Evidence: `tests/db/test_flags.py`: all 15 kind/reason combinations (5 accepted), unknown values, the three resolution fields set together, the detail shape; 240 tests pass with the database tests.
- **A version has one status: loading, failed, held, current or retired; held needs an open candidate flag and failed a load flag.** Two status columns described one lifecycle, and pending stood both for a load in progress and for a version waiting for a person.
  Evidence: database tests for each status and its flag rule; 271 tests pass with the database tests.
- **Routine loads raise no flag; a failed load leaves a failed version with a `check_failed` flag (`parse_failed` or `load_failed`) naming the file as listed in `corpus.yaml`, and a later successful load of the same bytes resolves it.** Flags are for what a person must handle; "same content, different packaging: no flag" now holds by construction, and a crash mid-load no longer leaves an orphan flag.
  Evidence: real-database load tests: a routine load and a repackaged file leave no flag, a parser timeout gives `parse_failed`, an embedding failure gives `load_failed` and the retry resolves it `fixed` by `system`, a crashed load is resumed; 271 tests pass.
- **A person approves or rejects a held candidate (approval moves the watch address to the candidate's address and confirms the source), a monitor can report an unreachable address, and sources unconfirmed for longer than a given age are flagged once each; confirming resolves that flag.** These are the brief's flagged cases; until now only the schema allowed them.
  Evidence: database tests for hold and approve, approval refused without `obtained_from`, one open overdue flag per source, confirmation and a new watch address resolving it; 300 tests pass with the database tests.
- **`scripts/answers.py saw` lists the answers that saw a version (by source key and label, or by id): date, question and the other versions each answer saw.** The brief requires listing earlier answers that relied on a retired version; the store held the links but nothing read them.
  Evidence: `answers_that_saw` database tests (newest first, other versions named by label or title, empty for an unseen version); script tests; 308 tests pass with the database tests.
- **When a load retires a version, the loader says how many earlier answers saw it.** Retiring a version is when those answers need a look; the count comes from the same transaction as the promotion.
  Evidence: real-database test (an answer that saw V1 gives 1 when V2 is promoted); a first version reports nothing; 312 tests pass with the database tests.
- **`scripts/flags.py` lists open flags and lets a person approve or reject a candidate, confirm a source, raise overdue flags (age from `CONFIRMATION_MAX_AGE_DAYS`, default 180, or `--max-age-days`), and report an unreachable address.** Every flag function needs a caller; this is a command line, not a review screen.
  Evidence: script tests for each subcommand, including the setting and its override; config tests for the default and an override; 322 tests pass with the database tests.
- **Chunks lose `token_count`, need an embedding, have one row per position in a version, and may have an empty section title; citations then fall back to the page.** `token_count` was read by nothing, and "Untitled Section" was invented text stored as data.
  Evidence: database tests for the unique position, the required embedding and the empty title; prompt and formatter tests give "T (V1.3), Page 3"; 330 tests pass with the database tests.
- **Chunks store their text without the `[title — section]` prefix; the embedding input is built from the columns with the same header, and the prompt shows each header once.** The title was copied into every chunk, and the model saw each header twice.
  Evidence: chunker, embedder, loader and prompt tests (embedded text `[Doc (V2) — S]` + text, stored text without it, one header per source in the prompt); 335 tests pass with the database tests.
- **Every version records the indexing settings it was loaded with (embedding model, dimensions, chunk size, overlap, chunker version); the store refuses current versions under different settings, and the loader stops before loading when the configuration differs.** Chunks embedded under different settings cannot be compared in one search.
  Evidence: database tests for the settings checks and for mixing (refused across sources, allowed for a lone source); a loader test stops before any load; a hash guard fails when `chunker.py` changes without a decision on `CHUNKER_VERSION`; 356 tests pass with the database tests.
- **Each answer points to the indexing and answer settings it used (top-k, rerank top-n and model, answer model, prompt version); `model_used` and the stored formatted answer are gone, and `GET /answers/{id}` derives the formatted answer and lists the versions seen.** An answer could not be traced to its prompt or reranker, and the formatted answer duplicated the response.
  Evidence: database tests for the settings references and checks; pipeline, logger, API and settings-row tests; a hash guard on `prompts.py` for `PROMPT_VERSION`; 367 tests pass with the database tests.
- **Parsed output is stored without the parser's links (`pdf_url`, `studio_link`, each block's `image_url`).** They point into the parser's service and are no part of the version's content.
  Evidence: `strip_links` tests; on all 11 cached parser outputs the extracted sections are identical with and without the links; 370 tests pass with the database tests.
- **Embedding waits out a rate-limit error and retries that batch (61 s, up to 5 times, both settings) instead of failing the load.** The last reload failed 5 versions on Cohere's per-minute limit and needed two reruns.
  Evidence: embedder tests: one rate-limit error is waited out, six give up after five waits, other errors are not retried, only the failing batch is re-sent; 375 tests pass with the database tests.
- **Eval questions have readable keys, fixed question and case types, required sources by key with the version they were written from, and numbered facts; an eval run records its settings and judge model, one result per question linked to the answer it scored, and per-fact verdicts; scores are a view, and a failed judgement is recorded without a score instead of failing the run.** Results were JSON with document ids that a reload invalidated, nothing linked a score to its answer, and one judge error lost the whole run.
  Evidence: database tests for each table, the review and score views (an unscored result is counted, never averaged as zero) and `record_eval_run`; runner tests (recall by source key, judge failure recorded and run continued, wrong verdict count); 414 tests pass with the database tests.
- **`scripts/load_eval_questions.py` loads eval questions from `eval/questions.yaml`, naming required versions by source key and printed label; the first two questions are the BKW baseline questions; once a question has results its question and facts cannot change; the old seed script is gone.** Questions referred to document ids, and the seed questions covered topics outside this corpus.
  Evidence: loader tests (label resolved to fingerprint, problems reported by question key before writing, missing file); database tests for replacing sources and facts and for the freeze once scored; 424 tests pass with the database tests.
- **The default answer model is `claude-sonnet-5-5` in `config.py` and `.env.example`.** The defaults still named `claude-sonnet-4-6`, while the model actually configured and used for the baseline is `claude-sonnet-5-5`; the answer-settings key names the model.
  Evidence: config tests for the default and `.env.example`; the answer-settings key test gives `top40-rerank8-rerank-v3.5-claude-sonnet-5-5-p1`.
- **The reranker imports Cohere's rate-limit error directly.** It named the error through an attribute path that resolves only once the SDK has loaded the module itself, which its lazy imports do not guarantee.
  Evidence: a test that one rate-limit error is retried, and that the reranker's error class is the SDK's; 428 tests pass with the database tests.
- **The prompt no longer uses the old project's words: no "field engineers" or "electrical installation documents", "higher rank" instead of "higher hierarchy priority", and `(Level: …, Rank: …)` instead of `(Type: …, Priority: …)`; `PROMPT_VERSION` is 2.** One vocabulary in code and docs; the rules themselves are unchanged (no tuning).
  Evidence: the vocabulary test now scans `prompts.py` with no exemption; a test that every rule is still in the system prompt; 429 tests pass with the database tests.
- **The text fingerprint follows the starting rule: the parser's blocks in order with headings and short blocks, without page headers, footers, page numbers and figures; its rule version is stored in the indexing settings and their key.** The old rule ignored headings and short values, so a changed heading or limit made no new version, while footers could make a false one.
  Evidence: fingerprint tests per included and excluded block type; on the 11 cached parses: 11 distinct fingerprints, all changed from the old rule, V1.2 still differs from V1.3 (`scripts/experiments/fingerprint_check.py`, output in `plans-local/fingerprint-check.txt`); 436 tests pass.
- **Page header blocks are page furniture: they no longer start a section or become chunk text; `CHUNKER_VERSION` is 2, and its guard covers the parser.** The parser treated the parser's `Header` blocks (letterhead, running titles, the BKW cover's version box) as section headings.
  Evidence: parser tests; on the 11 cached parses sections go from 421 to 419 and chunks from 1183 to 1181 (`scripts/experiments/sections_check.py`, output in `plans-local/sections-check.txt`); 439 tests pass with the database tests.

## 2026-11-21

- **Declare `cohere` and limit package discovery to `app/` and `eval/`.** The reranker imported an undeclared package, and the editable install broke once `data/` existed.
  Evidence: `pip install -e ".[dev]"` failed with "Multiple top-level packages discovered"; after the change it installs and 76/76 tests pass.
- **Align `.env.example`, config defaults and README: top-k 40, rerank 8, Anthropic as LLM provider, `COHERE_API_KEY` listed.** The example file still said top-k 20 and the README named GPT-4o.
  Evidence: `config.py` defaults were already 40 / 8 / anthropic; the other two files now match.
- **Embed with Cohere instead of OpenAI: `input_type` `search_document` for indexing and `search_query` for queries, `output_dimension` 1536, batches of 96.** Removes the OpenAI dependency without changing the `vector(1536)` schema.
  Evidence: a live call returns 1536-dimension vectors for documents and queries; embedder tests check input type, dimension and batching.
- **Eval judge: `claude-haiku-5-5` with structured output instead of `gpt-4o-mini`.** Removes the last OpenAI call; structured output means a malformed JSON reply cannot break the judge.
  Evidence: on a live check with one fact present and one absent, it scores 0.5; judge tests mock the Anthropic client.
- **Embedding model `embed-v5.0-pro` instead of `embed-v4.0`.** Newest Cohere embedding family, still at 1536 dimensions.
  Evidence: Cohere docs list 1536 among its dimensions (default 2048); a live call returns 1536 for documents and queries.
- **Grant `service_role` access at the end of `supabase/schema.sql`.** On a fresh project the secret key could not read tables created in the SQL editor.
  Evidence: before the grants, 6/6 tables and 2/2 search functions returned 42501 "permission denied"; afterwards all were readable and a test insert and delete succeeded.
- **Add `corpus.yaml` (path, title, issuer, level, scope, source_url per document).** One declared source of document metadata; level and scope map to the existing `doc_type`, `hierarchy_priority` and `grid_provider` columns.
  Evidence: titles, issuers and versions were read from each PDF's first pages; the `doc_type` strings come from the original design doc.
- **Add `scripts/load_corpus.py`.** Repeatable, idempotent load through the same steps as `POST /ingest`: skips completed documents, reloads partial ones, honours `max_pages`.
  Evidence: 6 loader tests; a second run after a rate-limit failure skipped 9 documents and reloaded the 2 failed ones, with no duplicates.
- **Add BKW Vorgaben V1.2 next to V1.3 as a separate document.** Reproduces the case of a new version published under a new name while the old one stays online.
  Evidence: the V1.2 cover reads "Version V1.2, valid from 1 March 2025"; the V1.3 cover reads "Ersetzt V1.2"; the text differs in section 4.
- **Anthropic call in `llm.py`: drop `temperature`, return the text block(s) instead of `content[0]`.** `claude-sonnet-5-5` rejects `temperature`, and with thinking the first block need not be text. Answers are no longer deterministic.
  Evidence: before the change every query failed with HTTP 400 "`temperature` is deprecated for this model"; 3 new tests; 86/86 pass.
- **Add `scripts/experiments/version_baseline.py` (stale and no-label variants), with no change to `app/`.** Measures how answers behave when versions are missing or unlabelled.
  Evidence: results in [baseline.md](baseline.md).
- **Fresh schema: documents are versions of sources, with scopes, flags and answer-to-version links; `hierarchy_rules` and the solar-specific columns removed.** Two versions of one source could both be searched, and nothing recorded which versions an answer used (see baseline).
  Evidence: 14 constraint and trigger tests against local Postgres 18 + pgvector pass (one current per source, pending needs a flag, immutable fingerprints, used versions undeletable); 87 others pass, 13 skip without `TEST_DATABASE_URL`.
- **`promote_version`, `reject_version` and `log_answer` as SQL functions; both search functions return current versions only, with source level, rank and scopes.** Retire-then-promote as separate client calls could leave zero or two current versions, and an answer could be stored without its versions.
  Evidence: 12 function tests on local Postgres pass, including a failed promotion that leaves the previous version current with its chunks, and search ignoring pending and retired chunks.
- **Remove `scripts/replace_document.py`; add content fingerprints and client methods for holding, promoting and rejecting versions.** Replacing a document in place erased the old version and made logged answers point at text that no longer existed.
  Evidence: 23 new unit tests (fingerprint normalisation, flag inserted before its pending version, RPC parameters); 130 tests pass with the database tests.
- **Loader and `POST /ingest` load versions by fingerprint; `corpus.yaml` lists sources with versions oldest first; `DELETE /documents` removed.** The path-keyed loader skipped a changed file at an unchanged path (the EKZ case), and deleting a version would break the answers that used it.
  Evidence: 25 new or rewritten tests: same bytes skipped, same text with new bytes dismissed with no open flag, an interrupted load resumed, a failed version stops later ones of its source; 146 tests pass.
- **Each answer is logged together with the distinct versions of its top-8 chunks; the prompt, query filter and legacy reranker read `level`, `authority_rank` and `scopes`.** Earlier answers that relied on a retired version must be listable, and answers shaped by uncited text count (baseline, unlabelled case).
  Evidence: pipeline test with chunks from d1, d1, d2 logs ["d1", "d2"]; prompt renders "(Type: operator, Priority: 2)"; reranker boosts when any of a chunk's scopes matches; 149 tests pass.
- **Row level security on every table with no policies, and `promote_version`, `reject_version` and `log_answer` executable only by `service_role`.** Postgres lets everyone execute new functions, and Supabase exposes the public schema to the `anon` key, so a public key could otherwise read the store or promote a version.
  Evidence: 13 access tests on local Postgres: with Supabase-like table grants, `anon` and `authenticated` see 0 rows in all 9 tables, cannot insert and cannot call the three functions; `service_role` still can; 162 tests pass.
- **Loader option `--parsed-cache DIR`: a file `DIR/<pdf sha256>.json` is used as the parser output instead of parsing; the dry run says per version whether it would be skipped, read from the cache or parsed.** Reloading after the schema change must not re-parse: re-parsing costs Reducto credits and could change the text between the "before" and "after" baseline runs.
  Evidence: 6 new tests (cache hit never calls the parser, a miss parses, no directory parses, the dry run reports skip/cache/parse); 172 tests pass.
- **`version_baseline.py` runs `current` (normal pipeline, logged with its versions) and `stale` (V1.2 rebuilt in memory from its retained parsed output); `nolabels` removed.** On the versioned store V1.2 has no chunks and two versions cannot reach the model together.
  Evidence: 5 helper tests; results in [baseline.md](baseline.md).
- **The loader does not yet pace its embedding calls.** The reload onto the versioned store hit Cohere's trial limit of 100,000 embedding tokens per minute and was completed by rerunning; recorded so the next reload expects it.
  Evidence: reload counts in [baseline.md](baseline.md), "Differences between before and after".
- **A pending version must be held by an open flag of its own source, enforced by a trigger on `documents`.** The check alone accepted a resolved flag or another source's flag, so a held version could exist with no open flag (whole-branch review).
  Evidence: 4 schema tests on local Postgres: a resolved flag, another source's flag, and setting back to pending with a resolved flag fail; with an open flag it succeeds.
- **The loader brings an existing source's issuer, level, listing address and scopes in line with `corpus.yaml` and says what changed.** Edits to an already-loaded source in `corpus.yaml` were silently ignored.
  Evidence: 6 tests: changed fields and scopes are updated and reported, a matching source is left alone, scope rows are replaced.
- **A pending version left by an interrupted load is dismissed when a new file has the same text but other bytes.** It made the unique text fingerprint fail on every run and blocked that source's later versions.
  Evidence: reproduced on local Postgres (UniqueViolation), now promoted with no open flag; 3 real-Postgres tests drive `load_version` through the actual constraints.
